> 日期：2026-08-13

## 改动清单

### 1. `main.md`
- 版本 v3.4.0 → **v3.5.0**，更新日期 → 2026-08-13
- 作用：版本递增 = 重读信号，触发管理会话按 §八 重新读取与同步

### 2. `compact-core.md`
- **§四头部新增"分发入口约定"**：
  - 清单表是规则库唯一分发入口，新增/更新规则文件的最后一步 = 同步本表（含文件版本与更新日期）
  - 版本递增本身是重读信号：表内条目标注版本比 AI 记忆新 → 必须重新 Read，NEVER 依赖旧记忆
- **§一新增第 15 条"会话收尾自检"**：
  - 用户表示收工/切换话题/新开会话前，必须跑沉淀判定：(1) 改动文档（第 10 条）；(2) 错误条目（ERROR/README.md 触发规则）；(3) 解决方案（.prompt）；(4) 项目级 bug（.issues/）
  - 全部不满足时明确说明"无"
  - 原因：沉淀类规则此前全靠自觉，20+ commit 的会话仍漏出改动文档

### 3. `ERROR/README.md`
- **新增"边界判定准则（操作化）"表**：
  | 情形 | 落盘位置 |
  |------|----------|
  | 跨项目可复用（语言/框架/平台坑、API 误用、工具链陷阱） | ERROR 库 |
  | 项目特有（本项目的 bug、设计决策、实现细节） | 项目根 `.issues/` |
  | 两者都要 | 双写：ERROR 记通用经验，`.issues/` 记项目上下文，各写侧重不复制全文 |
  | 判定不明确 | 默认 ERROR（跨会话价值优先），条目内注明项目出处 |
- **7 类表 ai-behavior 补判例**：修复时自己引入回归、被用户纠正的判断方向错误（如"修反了"）
