# 触发机制 (Trigger Mechanism)

> **可复用的"自动落盘"标准流程**。所有 AI 自动沉淀类行为（项目 bug 记录、AI 经验记录、改动文档、提示词/解决方案沉淀等）共用同一套执行逻辑，各自只提供参数。
> 版本: v1.0.0 | 更新: 2026-08-03 | 引用入口: `compact-core.md` §四 | 路径基准: 见 `ROOT.md`

---

## 设计思想

**机制 = 代码逻辑，行为 = 调用。**

```
机制（本文档）   = 一段公共函数：条件判定 → 位置解析 → 初始化 → 去重 → 写入 → 索引 → 交互
行为（注册表一行）= 一次调用：向机制传入自己的参数（触发条件、落盘位置、模板、交互要求）
新增行为         = 注册表加一行，NEVER 复制机制本体 / NEVER 另写一套流程
```

好处：触发条件因行为而异但流程统一；`workflow.md`、`.prompt`、`ERROR/` 等不再各自散落"记录流程"定义，只维护"注册表参数"。

---

## 一、机制接口（入参）

每个注册行为必须提供以下参数：

| 参数 | 说明 | 要求 |
|------|------|------|
| 行为名 | 注册表唯一标识 | 与引用处一致 |
| 触发条件 | 何时触发（判定规则） | **必须可判定**：具体到"什么情况触发"，NEVER 写"需要时""必要时" |
| 落盘位置 | 路径模板 | 支持 `{项目根}` 变量时按 §三 位置解析 |
| 初始化模板 | 目录首次出现时的骨架 | 目录 + README（含索引骨架） |
| 条目模板 | 单个条目的格式 | 必须存在于本文档或引用文件，NEVER 指向不存在的模板 |
| 索引规则 | 条目新增/更新后维护什么 | 有（路径）或 无 |
| 交互要求 | 无感 / 需确认 | 无感 = 静默执行不打扰；需确认 = 写入前先询问用户 |

## 二、执行流程（机制本体，所有行为共用）

```
step 0  条件判定   用本行为的触发条件判断；不满足 → 结束
step 1  位置解析   含 {项目根} 的位置 → 按 §三 规则定位落盘目录
step 2  初始化     目录不存在 → 创建 + 写入 README（用行为初始化模板）
step 3  检索去重   同主题已有条目 → 更新（+occurrences / last_seen / 补充新方案）
                  无 → 新建条目
step 4  写入条目   按行为条目模板
step 5  更新索引   按行为索引规则
step 6  交互       无感行为静默结束；需确认行为在 step 0 前已询问
```

## 三、位置解析规则（{项目根} 的解析）

用于落盘位置含 `{项目根}` 的行为（如 `.issues/`）：

1. 项目根已存在 `.issues/` 且在正常使用 → 沿用 `.issues/`
2. 项目根已建立 `docs/` 文档体系（README、设计、工作流程等文档集中于此）→ `docs/issues/`
3. 两者都无 → 默认项目根 `.issues/`
4. 同一项目内位置**固定**，NEVER 双写（根目录与 docs/ 各一份）

> 判定由 AI 按项目现状执行；结果在初始化时写入该项目 `.issues/README.md` 顶部，供后续会话直接读取，无需重复解析。

## 四、行为注册表

| 行为 | 触发条件 | 落盘位置 | 条目模板 | 索引 | 交互 |
|------|----------|----------|----------|------|------|
| 项目 bug 记录 | 见 `workflow.md` §9.4 | `{项目根}/.issues/`（按 §三 解析） | §9.4 模板 | 无（README 维护统计） | 无感 |
| AI 经验记录 | `workflow.md` §9.2（5 类场景） | `D:\Code\.Rules\ERROR\entries\` | `ERROR/README.md` 模板 | `ERROR/INDEX.md` | 无感 |
| 改动文档 | `workflow.md` §12.1（5-10 次修改 / 版本迭代 / 用户要求） | `docs/changelog/`（无约定时） | §12.2-12.3 | 无 | **需确认**（先询问再生成） |
| 提示词沉淀 | 会话后产生可复用高质量提示词 | `D:\Code\.prompt\{类型}\{标题}-{YYYYMMDD}\prompt.md` | `.prompt` 规范 | `.prompt\CLAUDE.md` 索引表 | 无感 |
| 解决方案沉淀 | 解决了一个技术问题且方案可复用 | `D:\Code\.prompt\解决方案\{类型}\{问题标题}-{YYYYMMDD}\solution.md` | `.prompt` 规范 | `.prompt\CLAUDE.md` 索引表 | 无感 |
| 项目审计待办 | 定期扫描发现项目健康问题（文档/git/版本） | `D:\Code\.Rules\docs\audit\{项目}\` | `docs/audit/README.md` 规范 | `docs/audit/README.md` 索引 | 无感（产出待办池） |

## 五、注册新行为（扩展机制）

1. 在 §四 注册表追加一行：行为名 | 触发条件 | 落盘位置 | 模板 | 索引 | 交互
2. 触发条件必须可判定（具体场景枚举，NEVER 用模糊词）
3. 落盘位置含 `{项目根}` 时，确认 §三 解析规则已覆盖；否则补充解析规则
4. 条目模板必须已存在（本文件或引用文件），并在此行给出引用路径
5. 在 `compact-core.md` §四 清单补一行按需加载入口，保持可发现性

## 六、目录初始化模板（README 骨架）

首次触发创建目录时写入，作为该目录的"锚点"（让 AI 一眼知道目录存在、机制已挂载）：

```markdown
# {目录用途} ({目录名}/)

> 由触发机制初始化于 {YYYY-MM-DD}。
> 机制: `D:\Code\.Rules\common\core\trigger-mechanism.md` | 条目规范: {引用文件}

## 位置解析结果

- 本项目落盘位置: {项目根}/.issues/ 或 {项目根}/docs/issues/（固定，不双写）

## 目录结构

{目录结构说明}

## 最近条目

| 日期 | 标题 | 状态 |
|------|------|------|
| ... | ... | ... |

## 统计

- 条目总数: 0
- 最后更新: {YYYY-MM-DD}
```
