# 错误存储与纠正系统 (Error Storage & Correction System)

> 错误资源库 — AI 自动进化的核心机制
> 存储位置：`D:\Code\.Rules\ERROR/`

---

## 定位

本系统是 AI 编码规则体系的**错误资源库**，负责：

1. **全量记录** — 任何问题都存储，不限代码错误
2. **检索优先** — 出现问题时先检索已有记录
3. **持续更新** — 重复问题更新次数，过时方案标记 deprecated
4. **自我纠正** — 记录 AI 自身被纠正的行为，避免重蹈覆辙

---

## 目录结构

```
ERROR/
├── README.md        # 本文档（系统说明）
├── INDEX.md         # 错误索引（按类型 + 标签自动维护）
└── entries/         # 错误条目
    └── {short-name}.md
```

## 错误类型（7 类）

| 类型 | 标识 | 说明 | 示例 |
|------|------|------|------|
| 代码错误 | `code` | 编译、运行时、逻辑错误 | 空指针、类型错误、死循环 |
| 配置错误 | `config` | 配置文件、环境变量问题 | YAML 格式错误、配置缺失 |
| 依赖错误 | `dependency` | 包管理、版本冲突 | 版本不兼容、包缺失 |
| 环境错误 | `environment` | 系统、工具链、平台问题 | OS 兼容性、路径问题、权限不足 |
| AI 行为纠正 | `ai-behavior` | AI 被纠正的行为 | 编造信息、违反原则、错误建议 |
| 工作流问题 | `workflow` | 开发流程、工具使用问题 | 流程遗漏、工具配置不当 |
| 知识盲区 | `knowledge` | 概念误解、API 误用 | 框架特性理解错误、最佳实践不知 |

## 条目格式

每个错误保存为独立的 Markdown 文件，命名规则：`{简短英文标识}.md`

```markdown
---
title: 错误名称
type: code | config | dependency | environment | ai-behavior | workflow | knowledge
tags: [tag1, tag2, tag3]
severity: critical | high | medium | low
status: resolved | open | deprecated
first_seen: YYYY-MM-DD
last_seen: YYYY-MM-DD
occurrences: 1
---

## 错误描述

**发生时间**: YYYY-MM-DD HH:MM（或"会话中"、"今天"等相对时间）
**错误内容**: 具体现象、报错信息、异常行为的完整描述
**错误诱因**: 导致问题发生的根本原因

## 环境信息

- 操作系统及版本
- 相关工具/框架版本
- 项目上下文（在做什么任务时出现）
- 其他影响复现的环境因素

## 复现步骤

1. 步骤一
2. 步骤二
3. ...

## 解决方案

暂无

<!-- 有方案时替换为： -->

### 方案一：xxx

1. 步骤一
2. 步骤二

## 预防措施

<!-- 如何避免再次发生 -->
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 错误名称，简洁明了 |
| `type` | 是 | 7 种类型之一 |
| `tags` | 是 | 关键词标签，小写连字符分隔 |
| `severity` | 是 | 严重程度 |
| `status` | 是 | `resolved`（已解决）/ `open`（待解决）/ `deprecated`（已过时） |
| `first_seen` | 是 | 首次出现日期 |
| `last_seen` | 是 | 最近出现日期 |
| `occurrences` | 是 | 出现次数，重复遇到时 +1 |
| 错误描述 | 是 | 时间 + 内容 + 诱因 |
| 环境信息 | 是 | 出错时的环境快照 |
| 复现步骤 | 尽量 | 能复现就写，不能就描述触发条件 |
| 解决方案 | 是 | `暂无` 或具体步骤 |
| 预防措施 | 可选 | 如何避免 |

## 自动存储策略

### 触发规则

```yaml
必须记录:
  - 用户主动报告的问题
  - 任务执行中的错误（构建失败、测试失败、运行时崩溃）
  - AI 行为被用户纠正（用户说"不对"、"应该是xxx"、"不要xxx"）
  - 排查过程超过 3 步的问题
  - 重复出现的问题（更新已有记录）

不记录:
  - 简单的语法修正（拼写、标点）
  - 用户明确表示不需要记录
```

### 存储流程

```
问题出现
  │
  ├──→ 搜索 ERROR/entries/ 是否有相似记录
  │      │
  │      ├── 有 → 参考已有方案解决，更新 occurrences 和 last_seen
  │      │
  │      └── 无 → 正常解决
  │
  └──→ 解决后
         │
         ├── 已有记录 → 更新（补充新方案、增加次数）
         │
         └── 新记录 → 创建条目，更新 INDEX.md
```

### 执行原则

1. **无感执行** — 存储过程不干扰用户，不主动汇报（除非用户查询）
2. **去重优先** — 相同问题更新而非新建
3. **如实记录** — 包括 AI 自身的错误和被纠正的行为
4. **保持更新** — 每次参考旧记录后评估是否仍然有效

---

## 检索优先规则

```yaml
出现问题后:
  1. 搜索 ERROR/entries/ 中是否有相似记录
     - 按类型筛选
     - 按标签匹配
     - 按关键词搜索（标题、描述、标签）
  2. 有记录 → 优先参考其方案，结合当前情况判断是否适用
  3. 无记录 → 正常解决，解决后存储

重要原则:
  - 检索结果仅供参考，不盲从旧方案
  - 环境可能已变化，旧方案未必有效
  - 每次参考后评估：有效→保持 / 已过时→更新或标记 deprecated
  - 保持批判性思维，检索是辅助而非替代
```

## 索引维护

`INDEX.md` 由 AI 自动维护，每新增或更新条目时同步更新。

索引组织方式：
- **按类型** — 7 种错误类型各一个分组
- **按标签** — 常用标签的交叉引用

---

## 与旧系统的关系

- `common/errors/` 和 `stacks/*/errors/` 为旧系统，**保留但冻结**
- 旧系统中的已有条目不迁移，遇到时按需迁移到 `ERROR/entries/`
- 所有新错误统一存入 `ERROR/entries/`
