## 错误描述

**发生时间**: 2026-10-15（Trace 项目整改第三轮，验收缺陷 F06）
**错误内容**: "默认配置只在缺失时安装"的实现是 `stat(config)` 不存在 → `save(default)`。两个分离步骤之间存在窗口：后台安装的检查完成后，用户/另一写入者成功保存自定义配置，安装的写入随后执行**普通替换**，覆盖刚写好的用户数据。验收实验在"最后一次检查之后、最终提交之前"注入另一真实服务保存，稳定复现覆盖。
**错误诱因**: ① TOCTOU（time-of-check-to-time-of-use）——检查与使用分离，中间窗口不可控；② 误以为"串行写入队列"能解决——队列只保证应用内同实例的先后顺序，不保证"只创建缺失文件"，另一个实例/外部写入者完全绕开；③ 修复第一版把检查搬进同一队列，仍留有最终替换的窗口——**多加一次检查不是修复，窗口只是变小**。

## 环境信息

- Electron 主进程 + Node fs；同一配置文件的多写入者（后台安装器、用户保存、外部同步）

## 复现步骤

1. 安装器 stat 发现配置不存在
2. 在安装器最终写入前，另一写入者完成用户配置保存
3. 安装器用覆盖式写入（rename 替换）提交默认配置 → 用户配置丢失

## 解决方案

**最终落盘必须使用"目标存在即失败"的原子原语**：写临时文件 → `fs.link(tmp, target)`——硬链接创建是原子的，目标已存在时 EEXIST 失败，永远不会替换。捕获 EEXIST 转为"放弃安装"。同队列检查保留为快速路径，但正确性不依赖它。

```
// writeJsonAtomic(target, data, targetMustNotExist):
await this.link(tmp, target)   // EEXIST = 别人先写了 → 放弃
```

## 验收教训（同等重要）

- 回归必须复现**窗口场景**（gate 阻塞一侧写入、另一侧在窗口内落盘），只测"重复串行启动幂等"测不到竞态。
- 修复方宣布"全部修复"前，验收方用缩小范围的边界实验独立复现——本轮第一版修复即被验收实验证伪，第二版才真正关闭。
