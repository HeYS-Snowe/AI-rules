## 错误描述

**发生时间**: 2026-08-13 会话中（deepcode-cli spinner 对齐问题，反复三次才修对）

**错误内容**: 同一组动画帧里混用不同宽度类的字符（如 1 格的 `·` 与按项目自算表计 2 格的 `◆`、定义上全角的 `・`），导致渲染时行内容左右跳动、视觉中心漂移。三次踩坑：① 混用窄点/宽菱形帧；② 引入全角 `・`（U+30FB）作为唯一 2 格字符；③ 修复时按"自认为的渲染宽度"做感知补齐，实际终端渲染宽度不同，补齐方向反了。

**错误诱因**: 同一个字符的宽度存在三个可能不一致的答案——Ink/string-width 测量表、终端实际渲染（受字体/EAW 设置影响）、项目自算表（如 diffCharWidth 提升区间）。修复必须基于**用户终端实测**，而不是库的测量结果或猜测。

## 环境信息

- Windows Terminal + Git Bash + Ink 7（string-width 8）
- 实测：用户终端里 `◇◈◆` = 1 格、`・` = 2 格、`·` = 1 格

## 复现步骤

1. 动画帧集混入不同 EAW 宽度的字符
2. 在目标终端观察切换帧时列位置是否漂移

## 解决方案

### 方案一：全帧同一宽度类 + 固定槽宽（CC SpinnerGlyph 模式）

帧集内所有字符实测宽度一致，外层用固定宽度 Box 钉位，槽宽恒定。

### 方案二：先实测后补齐

用目标终端跑 demo 输出两帧对比列位置（空格数差异 = 宽度差），再决定补齐方向。别信 string-width 的 ambiguous 默认值。

## 预防措施

- 动画帧集设计规则：**所有帧必须同一宽度类**，换帧字符前先实测
- 给审查用户看效果时输出带列对齐的 demo，让实测数据说话
