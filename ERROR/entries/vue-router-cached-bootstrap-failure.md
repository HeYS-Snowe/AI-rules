## 错误描述

**发生时间**: 2026-10-09
**错误内容**: 用户实测登录入口对同一认证模式接口连续请求两次。业务路由守卫第一次初始化失败后重定向到登录路由，第二次守卫调用 store 初始化；store 只缓存进行中的 Promise，没有缓存失败终态。
**错误诱因**: 将单次请求的 in-flight 去重误当作路由生命周期内的重复调用保护，遗漏失败状态在重定向后的再次调用。

## 环境信息

- Vue 3、Vue Router、Pinia。
- 项目上下文：TerraScribe DEMO5.0 本地认证初始化；后端认证路由缺失触发该失败路径。

## 复现步骤

1. 从受保护业务路由进入应用。
2. 让首次认证模式查询失败。
3. 路由守卫重定向登录页并再次调用初始化。

## 解决方案

初始化入口除共享进行中的 Promise 外，还应缓存失败终态，直到显式重试动作重置状态：

```js
if (status.value === 'error') return status.value
```

显式重试负责清除失败状态后重新执行初始化；不要通过失败自动放行受保护路由。

## 预防措施

- 为路由守卫可重复调用的初始化流程定义成功、失败、进行中和显式重试的状态语义。
- 对失败状态的自动再次调用，应确认其是否有意；重试入口要与导航副作用分离。
